6. Conclusion

Reachability is highly consistent across observers — the same nodes are up or down almost regardless of who is probing. Performance and grades are observer-relative and materially geography-sensitive — the same 42 nodes graded by both runs agree only 52.4% of the time on letter grade, correlate weakly on score (r=0.18), and differ by a mean of 11.0 points across observer locations. A single-vantage-point health report describes "network health as seen from here," not an absolute property of the node.

7. Limitations

  • Each region was probed exactly once — no repeated rounds to separate noise from a stable geographic effect.
  • The two runs were not simultaneous: their reported chain tips were roughly 153 blocks apart, so the networks were probed at slightly different points in time.
  • Illinois is a deterministic 50-node sample (fixed selection), not a random sample, so it should not be read as statistically representative of the full 2,605-node population.
  • Concurrency for the SE Asia run is not recorded in its CSV output, so probing parallelism cannot be compared directly between runs.
  • Sync depth is inferred rather than stated for SE Asia: every SE Asia row shares a uniform headers_target of 52,611, consistent with a ~50,000-block depth setting, but it is inferred, not logged. Illinois explicitly used --sync-depth 50000, filters enabled, concurrency 8, and a 180-second timeout.

8. Recommendation for future multi-vantage reports

  • Run every vantage point with the identical explicit configuration (sync depth, filters, concurrency, timeout) and log that configuration in every run's output — never leave it to be inferred.
  • Run simultaneous, repeated rounds from each region rather than one-off single passes, so transient network conditions can be separated from persistent geographic effects.
  • Aggregate reachability across vantage points per node as a quorum (e.g. majority-reachable), plus a median and worst-case score per node, instead of trusting any single observer's grade.
  • Always record region, timestamp, and full probe configuration alongside every report so cross-run comparisons like this one don't require reconstruction after the fact.
